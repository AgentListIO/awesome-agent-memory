> Persistent memory, recall, knowledge graphs, and context tools for AI agents.

37 projects · Upstream documentation checked 2026-09-30. Curated by [agentlist.io](https://www.agentlist.io).

**Help your agent pick up where you left off.**

Start with what your agent keeps forgetting. Resuming a conversation, remembering project decisions, learning personal preferences, and sharing knowledge across a team are different jobs. Choose a memory tool for the information you need to preserve and the place you need to recall it.

Tools with an explicit agent-memory or persistent-context interface. General databases and document search engines are excluded unless the linked project supplies an agent-facing memory layer.

## How to choose

- Works with: Is there a documented integration for your agent, or will you need to build one using an SDK, API, or MCP server?
- Runs where: Where are memories stored and processed? Can you operate the storage and retrieval service yourself?
- Needs access to: Does it ingest selected notes, conversations, repository files, or every tool interaction? Can you control what is captured?
- Keeps what: Does it preserve transcripts, facts, relationships, preferences, or procedures? Can you inspect, correct, export, and delete them?
- Human involvement: Who decides what becomes a memory, when it is recalled, and when outdated information is removed?
- Main limitation: How will you detect irrelevant recall, conflicting memories, or information leaking between projects and users?

Use these questions to narrow your shortlist. An entry’s source link records the documentation used for its description; it does not mean every question above has been answered or tested. Treat undocumented capabilities as unknown, and confirm requirements against the linked project before adopting it.

## Memory services and frameworks

- [Cognee](https://github.com/topoteretes/cognee) - Python library that turns documents, conversations, and code into a knowledge graph with remember, recall, improve, and forget operations scoped by dataset. The README documents local extraction and embedding with small models when no LLM key is set, plus Claude Code and Codex plugins, an MCP server, and Cognee Cloud. Forget removes an item or a dataset; the README does not describe an export format separate from the graph you query. **Python library.**
- [Hindsight](https://github.com/vectorize-io/hindsight) - Memory server whose clients call retain, recall, and reflect on a bank of world facts, experiences, observations, and mental models. You run the Docker server with its embedded Postgres or an external database, or use Hindsight Cloud; Python, TypeScript, an LLM wrapper, coding-agent installers, and a per-bank MCP endpoint are documented. Retain uses an LLM to extract facts and entities, and the README does not document a human approval step before that write. **Memory server.**
- [LangMem](https://github.com/langchain-ai/langmem) - Python tools an agent can call to save and search long-term memory during a conversation, plus a background manager that extracts and consolidates onto a LangGraph store. The README's in-process store disappears on restart, and a database-backed store such as AsyncPostgresStore is what keeps memories. On the hot path the agent decides what to record, you supply the LLM key, and LangMem itself is not a hosted memory service. **Python library.**
- [Mem0](https://github.com/mem0ai/mem0) - Memory layer offered as a Python library, a self-hosted server, and a managed platform, with add and search scoped by user, session, or agent. The README's newer extraction path keeps agent-confirmed facts and does not overwrite or delete during that pass, so memories accumulate until something else removes them. Self-hosted auth is on by default, and the repo's coding-assistant skills teach integration rather than replacing the SDK or API. **SDK and managed service.**
- [Memobase](https://github.com/memodb-io/memobase) - User-profile backend that buffers chat blobs and flushes them into a structured profile and an event timeline. The README says processed blobs are removed unless storage config keeps them, so the durable record is the profile and events rather than the original transcript. It is Apache-2.0, and the README points MCP clients at Memobase-MCP under src/mcp. **Memory backend.**
- [Redis Agent Memory](https://github.com/redis/agent-memory-server) - Managed memory layer on Redis Cloud, called through a Python SDK, a TypeScript SDK, or REST. Session memory holds the live conversation with a configurable TTL, and a background job promotes extracted facts into long-term text and vector embeddings. The README says the V0 tree is an earlier open-source server kept as research, not the supported service, and it does not document a person reviewing each promoted fact. **Managed memory service.**
- [Supermemory](https://github.com/supermemoryai/supermemory) - Memory API that extracts facts and user profiles from conversations and can search those together with uploaded documents. Plugins and a hosted MCP server are documented for Claude Code, Muse Code, Cursor, Codex, OpenCode, OpenClaw, and Hermes, and a local binary serves the same API, including an Ollama option the README says can stay offline. Container tags separate projects; the memory tool can save or forget, but extraction is also automatic and the README does not document a review queue. **Memory platform.**
- [Memori](https://github.com/MemoriLabs/Memori) - Python and TypeScript wrapper that registers an LLM client, attributes each call to an entity and a process, and persists and recalls in the background. The README quickstart is a hosted API key from app.memorilabs.ai, and without attribution it says Memori cannot make memories. Linked BYODB docs show a database you connect, including a local SQLite file. OpenClaw and Hermes plugins and an HTTP MCP endpoint for Claude Code, Cursor, Codex, Warp, and Antigravity are documented; the OpenClaw plugin also records tool calls and outcomes after a turn. **Memory SDK.**
- [memU](https://github.com/NevaMind-AI/memU) - Personal memory stored as Markdown skills, with a sidecar per coding agent that slices session logs and asks that agent to distill them. The README says MemoryService only stores, embeds, and retrieves that Markdown and does not call an LLM itself, using either a hosted API key or a self-hosted store. The support matrix excludes ChatGPT chat mode and Claude chat and Cowork, and uninstall keeps the store unless you explicitly erase it. **Memory sidecar.**
- [EverOS](https://github.com/EverMind-AI/EverOS) - Local-first Python runtime that writes conversations, files, and agent trajectories to Markdown and indexes them with SQLite and LanceDB. A local HTTP API adds, flushes, and searches memories, and the README documents plugins for DeepSeek Harness, Hermes, OpenClaw, and Dify, plus EverOS built into Raven. The demo can run without a key, while the documented init path expects an OpenRouter key, and flush is the step that makes a fact durable in the Markdown files. **Local memory runtime.**
- [MemOS](https://github.com/MemTensor/MemOS) - Memory service with one API to add, search, edit, and delete an inspectable graph of text, images, and tool traces. The README uses memory cubes to separate users, projects, and agents, and natural-language feedback can correct an entry. You can call a cloud API, run the service with Docker, or install local plugins for OpenClaw, Hermes, and DeepSeek Harness, with a cloud plugin also documented for OpenClaw and DeepSeek Harness. **Memory service.**
- [Honcho](https://github.com/plastic-labs/honcho) - Service that stores messages and events, updates peer representations in the background, and returns search results or a natural-language answer. The README documents a managed API, a local honcho start stack, and a self-hosted FastAPI server, with Python and TypeScript clients in this repo. Plugins and MCP are listed for Claude Code, Codex, OpenCode, Hermes, and other clients; you choose which messages to store, and the README does not document an approval step before background reasoning changes a peer. **Memory service.**
- [ReMe](https://github.com/agentscope-ai/ReMe) - Memory kit that keeps durable memory as ordinary Markdown with frontmatter and wikilinks, so a person and an agent edit the same files. A local service is reachable by CLI, HTTP, MCP, or an in-process Python API, and the README lists QwenPaw, DeepSeek Harness, Hermes, and OpenClaw. BM25 search works without embeddings, but embeddings are required for the automatic memory jobs, and the files themselves are the copy you can move or back up. **Markdown memory kit.**
- [MemMachine](https://github.com/MemMachine/MemMachine) - Memory server that splits episodic conversation into a graph database, long-term user facts into SQL, and the current session into working memory. A Python client, REST, a TypeScript SDK, and MCP talk to a server you run or to the hosted platform, and the README lists LangChain, LangGraph, CrewAI, LlamaIndex, AWS Strands, and Dify. The caller sets user, agent, and session ids, and the README does not document a human review before add. **Memory server.**
- [Caura](https://github.com/caura-ai/caura) - Governed memory service, formerly MemClaw, where agents write plain text and the server stores and searches it for one agent or a fleet. The README documents REST and MCP, a standalone Docker stack with auth bypassed for a local trial, and agent-scoped credentials when agents share a deployment. Trust tiers and visibility scopes limit cross-agent reads, writes, and deletes, and the README does not document a file export separate from the API. **Memory service.**
- [TencentDB Agent Memory](https://github.com/TencentCloud/TencentDB-Agent-Memory) - Self-hosted hub that turns conversations, documents, and code into chat memory, skills, a wiki, and a code graph, then serves them through a proxy used as the agent's model base URL. The README says that proxy path needs no plugin and documents Claude Code, CodeBuddy, and DeepSeek Harness. People review and equip assets in Memory Hub, personal skills stay private until shared, and the release notes list skill export as later work rather than a current feature. **Team memory hub.**
- [OpenViking](https://github.com/volcengine/OpenViking) - Open-source context database, not only a memory store: documents, code, user memories, and skills live on one viking:// filesystem an agent can list and read. Committing a session archives the conversation and writes extracted memories as Markdown the README says you can edit. Native integrations, MCP, a desktop console for macOS and Windows x64, and optional resource ACLs are documented, and the README says to configure authentication before exposing the server beyond localhost. **Context database.**
- [LongMemory](https://github.com/CaviraOSS/LongMemory) - Local TypeScript engine for ingest and recall, exposed as a library, CLI, HTTP service, MCP server, and dashboard, with SQLite as the durable file. The Python package is only an HTTP client for that server, not a second engine. The README documents strict and associative recall and treats stored content as immutable; in-memory mode needs no database and ends when the process closes. **TypeScript library.**
- [Memorix](https://github.com/AVIDS2/memorix) - Local memory for coding agents, kept in SQLite under the Git project and opened through MCP, hooks, a CLI, and a small SDK. The README lists setup for Claude Code, Codex, Cursor, and other MCP agents, and says hooks capture only where that agent exposes the events. Knowledge pages are review-gated so a proposal does not replace a reviewed page, and optional sync still treats the local SQLite file as the canonical store. **Local memory service.**
- [TeleMem](https://github.com/TeleAI-UAGI/telemem) - Python memory layer the README presents as a Mem0-compatible add and search API, with a separate memory profile per character. The slogan says it is fully local on Qwen and FAISS by default, but the quickstart sets an OpenAI API key and Memory() follows Mem0 provider defaults. A local Qwen endpoint and FAISS path are a separate config file. An MCP server exposes the tools, the docs describe a video path from frames to captions into a vector store, and the README says it disables mem0 telemetry by default. **Python library.**
- [Zep](https://www.getzep.com/) - Hosted context service that builds graphs from business data, documents, and conversations and returns a slice for a task. The site documents a managed cloud, a cloud option with customer-managed keys, and a VPC deployment. Graphiti is the open-source graph library and is listed separately. The getzep/zep GitHub repository is examples, not this service. **Hosted memory service.**

## Graph, file, and local recall

- [Basic Memory](https://github.com/basicmachines-co/basic-memory) - MCP server that stores a knowledge base as Markdown files on disk, with observations and wikilinks that both a person and the agent can edit. The README documents a local install for Claude, Codex, Cursor, ChatGPT, and other MCP clients, plus optional hosted sync of the same files. Search can be keyword or semantic, cloud notes stay Markdown, and the README says those notes can be exported back to local files. **MCP server.**
- [Graphiti](https://github.com/getzep/graphiti) - Python framework for a temporal knowledge graph of entities, facts with validity windows, and episodes that keep the raw ingested text. You run it and bring your own graph database; an included MCP server is documented with Neo4j, retrieval mixes embeddings, keywords, and graph traversal, and custom types use Pydantic models. Zep's hosted context service is listed separately and is not operated by this library. **Graph library.**
- [Memvid](https://github.com/memvid/memvid) - Library that stores documents, embeddings, and metadata in one append-only .mv2 file, with Python, Node, Rust, and a CLI. Each frame is immutable, so a later search can still read an earlier state of the file, and the README shows put and search from application code with optional local or API embeddings. It does not document an MCP server or a rule for which agent turns become memories, and it marks the older QR-based format deprecated. **File memory library.**
- [GBrain](https://github.com/garrytan/gbrain) - Local memory of explicit facts with sources, including correction and withdrawal, shared with agents you already run. The README's memory-only path covers Grok Bot, Muse, Codex, and Claude Code, including MCP on a tailnet, starting from keyword search before optional embeddings or synthesis. Markdown export is not a full database backup, and the README says local files and shared database credentials sit outside the grant filters used for remote clients. **Local memory service.**
- [MemPalace](https://github.com/MemPalace/mempalace) - Local tool that stores conversation text verbatim and searches it semantically, grouping people and projects so a query can be scoped. The default index is ChromaDB, other backends can be plugged in, agents use the CLI or an MCP server, and the README says nothing leaves the machine unless you opt in. The README, re-read on 2026-09-30, says the only official sources are this GitHub repository, the PyPI package mempalace, and mempalaceofficial.com, and that other domains may be impostors. **Local memory tool.**
- [MCP Memory Service](https://github.com/doobidoo/mcp-memory-service) - Self-hosted service with REST, MCP, a CLI, and a dashboard for memories and a knowledge graph of typed links such as causes and fixes. The README documents on-machine ONNX embeddings and an agent id header that tags memories for scoped retrieval, and it lists LangGraph, CrewAI, AutoGen, Claude, and other HTTP or MCP clients. Consolidation can compress older memories, and the README does not require a person to approve each store. **Memory server.**
- [projectmem](https://github.com/riponcm/projectmem) - Local record of coding work, stored as typed events such as issues, attempts, fixes, and decisions in a .projectmem directory in the project. One MCP server, with no project root argument, serves every registered project for Claude Code, Claude Desktop, Cursor, Antigravity, and Codex. The README says it makes no network calls unless you enable an update check, Git still holds the diff, and no cloud copy of the directory is documented. **MCP server.**
- [Engram](https://github.com/Gentleman-Programming/engram) - Go binary, not the DeepSeek Engram paper, that keeps curated project memory in one local SQLite file with full-text search. CLI, HTTP, MCP, and a TUI serve Claude Code, OpenCode, Gemini CLI, Codex, Copilot, Cursor, and other MCP agents. The documented contract is to save decisions, fixes, and a session handoff on purpose rather than every tool transcript, and the local database stays authoritative if you also use Git sync or the optional cloud. **Local memory binary.**

## Agent-integrated memory

- [claude-mem](https://github.com/thedotmack/claude-mem) - Plugin that records tool-use observations through lifecycle hooks, summarizes them, and injects a slice into a later session. The README says a global npm install does not register hooks or the worker, and it documents Claude Code, OpenCode, Codex, Gemini, Hermes, Copilot, OpenClaw, and a Grok Bot log watcher, plus MCP search. Capture is automatic unless you mark a span private, and the installer lets you pick a hosted observer or your own model key. **Agent plugin.**
- [Letta Code](https://github.com/letta-ai/letta-code) - Stateful agent harness whose agents rewrite memory blocks, skills, and prompts, with context tracked in MemFS and able to sync to a Git repository. You use the CLI, a desktop app for macOS, Windows, and Linux, chat.letta.com, or documented channels. Letta Cloud stores memory, identity, and conversations by default, and a local backend is available. Permission modes set what is auto-approved or auto-denied. The README says AgentFile export and import were removed, while memory import and export and conversation transcript export remain. **Agent harness.**
- [Letta repository](https://github.com/letta-ai/letta) - Platform for stateful agents, formerly MemGPT, documented here as an App Server for local or self-hosted agents, desktop and browser apps, Slack, Telegram, and Discord, a TypeScript SDK, and Letta Cloud. This README says the active source, including the harness and the runtime behind those apps, now lives in letta-ai/letta-code, which is listed separately. The archive branch keeps the retired V1 API server and is not the current interface, and this README does not describe a separate memory file format. **Moved source.**
- [agentmemory](https://github.com/rohitg00/agentmemory) - Local memory server with MCP, hook, and REST adapters shared by coding agents such as Claude Code, Cursor, Codex, Gemini CLI, Hermes, OpenClaw, and OpenCode. The README says it captures agent activity, compresses it, and can inject it into a later session, storing state outside the repository unless you set a data directory. Keyless mode uses keyword search, semantic search needs an embedding provider, and native Windows does not auto-install the pinned engine binary. **Coding-agent memory.**
- [MemoraX Code](https://github.com/memorax-ai/memorax-code) - Plugin that attaches repository knowledge, procedures, and preferences to Codex, Claude Code, Cursor, OpenCode, Trae, and other coding CLIs the installer detects. Setup keeps an API key locally, search and writeback need network access, and on Linux the README says guest credentials need secret-tool. Repo memory can be built by a background subagent, Cursor may still request ordinary tool approvals, and the README does not document an offline store. **Coding-agent plugin.**
- [mem9](https://github.com/mem9-ai/mem9) - Shared memory server whose plugins call store, search, get, update, and delete on a hosted API or a server you run. The README lists OpenClaw, Hermes, Claude Code, OpenCode, Codex, DeepSeek Harness, and Dify, and says storage, search, and policy stay on the server. Self-hosting uses TiDB, Postgres, or db9 with a tenant database behind the API key, a dashboard is included, and a single-file local mode is not documented. **Memory server.**

## Retrieval adapters

- [Qdrant MCP Server](https://github.com/qdrant/mcp-server-qdrant) - Official MCP server over Qdrant vector search. The README calls it a semantic memory layer, but it does not document a knowledge graph, a file workspace, or a policy for what becomes a memory. You operate Qdrant, with a server URL or a local path, through qdrant-store and qdrant-find; embeddings default to local FastEmbed, read-only mode disables storing, and nothing in the README reviews a write before it lands. **MCP server.**

## Unmaintained references

- [Motorhead](https://github.com/getmetal/motorhead) - Session memory server for LLM chats. The README says the project is deprecated and that support is no longer maintained. Clients get, post, and delete a session window that is summarized as it grows, optional long-term search uses Redisearch and defaults to off, and the documented server expects a Redis URL. **Memory server.**
